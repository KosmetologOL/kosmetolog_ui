# D8 · Захистити CSV-експорт від formula injection

| Пріоритет | Оцінка | Епік | Залежить від |
|---|---|---|---|
| **P2** | S (до пів дня) | Автентифікація і безпека | — |

## Контекст

escapeCsvField у frontend/src/lib/csv.ts:3–8 екранує лише лапки, коми й переноси рядків. Значення, що починаються з =, +, -, @ (а також TAB/CR), потрапляють в експортований файл як є — Excel/LibreOffice інтерпретують їх як формули (класика: =HYPERLINK(…) для ексфільтрації). Експорт використовують три довідникові менеджери: CRUDManager.tsx:189, HomeCare/HomeCaresManager.tsx:201 і Admin/CategoryItemsManager.tsx:180. Дані вводять лише admin/doctor, тож практичний ризик малий, але CSV-файли довідників можуть передаватися третім особам. Стандартна нейтралізація — префікс «'» перед небезпечним першим символом; при реімпорті через parseCsv префікс треба симетрично знімати, інакше він осяде в даних.

## Кроки реалізації

1. У frontend/src/lib/csv.ts додати константу і оновити escapeCsvField (рядки 3–8) — готовий код:
const FORMULA_PREFIX = /^[=+\-@\t\r]/;

const escapeCsvField = (value: string): string => {
  const guarded = FORMULA_PREFIX.test(value) ? `'${value}` : value;
  if (/[",\r\n]/.test(guarded)) {
    return `"${guarded.replace(/"/g, '""')}"`;
  }
  return guarded;
};
(префікс додається до перевірки лапок, тож поле з комами далі коректно піде через гілку з лапками).
2. Симетрія при імпорті: у parseCsv перед фінальним return (рядок 61) додати зняття захисного префікса:
const unguard = (cell: string) =>
  cell.startsWith("'") && FORMULA_PREFIX.test(cell.slice(1))
    ? cell.slice(1)
    : cell;

return rows
  .map((cells) => cells.map(unguard))
  .filter((cells) => cells.some((cell) => cell.trim() !== ""));
3. Споживачі (CRUDManager.tsx, HomeCaresManager.tsx, CategoryItemsManager.tsx) не змінювати — вони працюють через toCsv/parseCsv.
4. npm run lint у frontend/.

## Критерії приймання

- [x] Значення, що починається з =, +, -, @, TAB або CR, в експортованому CSV має префікс ' (напр. '=1+2)
- [x] Цикл експорт → імпорт повертає початкові значення без залишкового префікса '
- [x] Наявне екранування лапок, ком і переносів не змінилося (поле з комою — в лапках; " подвоюється)
- [x] Легітимні значення з апострофом на початку (не перед формульним символом) не зачеплені імпортом

## Ручна перевірка

> У проєкті немає тест-сьюти — перевірка виконується вручну на локальному дев-середовищі. Жодних дій проти продакшн-БД.

1. Локально (backend з тестовою БД + frontend): у довіднику «Обстеження» створити запис з назвою =1+2 і рекомендацією, що починається з «- пункт списку».
2. Натиснути експорт CSV → відкрити файл текстовим редактором: поля виглядають як '=1+2 і '- пункт списку; відкрити в LibreOffice/Excel — формула НЕ обчислюється.
3. Імпортувати цей самий файл назад (кнопка імпорту менеджера) → у списку значення знову =1+2 і «- пункт списку», без апострофа на початку.
4. Регресія екранування: запис з назвою a,b"c → експорт → імпорт → значення без змін.
