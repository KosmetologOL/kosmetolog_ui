# B11 · Перевмонтовувати CreateReportForm при зміні patientId (key на роуті)

| Пріоритет | Оцінка | Епік | Залежить від |
|---|---|---|---|
| **P2** | S (до пів дня) | Шлях збереження листа | — |

## Контекст

Ефект завантаження даних у CreateReportForm (депс [patientId], рядки 169–283) не розрахований на зміну пацієнта без розмонтування компонента — а це можливо на тому самому маршруті /create-report/:patientId, наприклад через браузерні back/forward між листами двох пацієнтів. У такому переході loading лишається false (стара форма видима), savedSnapshot не скидається (isDirty рахується від чужого знімка), а selected*-стани оновлюються лише в гілці `if (reportData)`: якщо в нового пацієнта звіту немає, у формі залишаються обстеження/процедури ПОПЕРЕДНЬОГО пацієнта, які можна зберегти в чужий лист. Сьогодні прямого UI-переходу A→B без розмонтування немає, тож баг латентний, але фікс копійчаний: перевмонтовувати форму через key. Це також захищає від гонки відповідей між двома пацієнтами (стара форма з її запитами знищується).

## Кроки реалізації

1. Замінити вміст frontend/src/pages/CreateReportPage.tsx на:
```tsx
import CreateReportForm from "#components/ReportForm/CreateReportForm";
import React from "react";
import { useParams } from "react-router-dom";

const CreateReportPage: React.FC = () => {
  const { patientId } = useParams();

  // key: React перевмонтовує форму при зміні пацієнта — стан і запити
  // попереднього пацієнта не перетікають у форму наступного.
  return <CreateReportForm key={patientId} />;
};

export default CreateReportPage;
```
2. Виконати `npm run lint` у frontend/.

## Критерії приймання

- [x] При зміні patientId в URL на тому самому маршруті форма повністю перевмонтовується: показується скелетон завантаження, всі selected*-стани, savedSnapshot і reportId скинуті.
- [x] Дані (обстеження/процедури/засоби) пацієнта A ніколи не зʼявляються у формі пацієнта B, навіть якщо у B немає звіту.
- [x] Звичайне відкриття листа зі списку пацієнтів працює без змін.

## Ручна перевірка

> У проєкті немає тест-сьюти — перевірка виконується вручну на локальному дев-середовищі. Жодних дій проти продакшн-БД.

1. Локально: створити двох тестових пацієнтів — A зі збереженим листом (додати обстеження), B без листа.
2. Відкрити лист A, повернутися на /patients, відкрити лист B; тепер браузерними кнопками «Назад»/«Вперед» переходити між /create-report/A і /create-report/B: при кожному переході має мигати скелетон, форма B — порожня (без обстежень A), форма A — зі своїми даними.
3. Відкрити лист будь-якого пацієнта зі списку і зберегти — регресій немає.
