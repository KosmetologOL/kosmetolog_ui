# C9 · Схуднення HTML-експорту і шрифтів: WOFF2, оптимізація лого, швидка конвертація в base64

| Пріоритет | Оцінка | Епік | Залежить від |
|---|---|---|---|
| **P2** | M (1–2 дні) | Експорт: HTML і DOCX | — |

## Контекст

У кожен експортований HTML-лист вбудовуються два TTF-шрифти Noah (Regular 128 КБ + Bold 135 КБ → ~352 КБ у base64) та logo.png на 159 КБ (~212 КБ як data-URL) — разом ~0.6 МБ службового вмісту на кожен лист. Сам застосунок теж вантажить усі 4 накреслення Noah як TTF (~529 КБ, index.css:3-33; font-display: swap уже є, тож перший рендер не блокується — втрата лише в байтах). Додатково fetchAsBase64 (generateReportHtml.ts:153-162) конвертує байти через reduce з посимвольною конкатенацією рядка — O(n²) на сотнях тисяч байтів, відчутна затримка на кожному експорті, хоча поруч уже є fetchAsDataUrl через FileReader (рядки 164-172). Потрібно перевести шрифти на WOFF2, оптимізувати лого і прибрати повільну конвертацію.

## Кроки реалізації

1. Конвертувати 4 TTF з frontend/src/fonts/ у WOFF2 (наприклад: pip install fonttools brotli; fonttools ttLib.woff2 compress Noah-Regular.ttf — і так для всіх). За бажання попередньо субсетнути до кирилиці+латиниці+пунктуації через pyftsubset (--unicodes=U+0000-00FF,U+0400-04FF,U+2010-2026,U+02BC) — типова економія ще 60-70%. Файли .woff2 покласти поруч із TTF.
2. У frontend/src/index.css у всіх чотирьох @font-face (рядки 3-33) розширити src: url("./fonts/Noah-Regular.woff2") format("woff2"), url("./fonts/Noah-Regular.ttf") format("truetype"); (аналогічно Bold/RegularItalic/BoldItalic). font-display: swap НЕ чіпати — він уже правильний.
3. У frontend/src/components/ReportForm/html/generateReportHtml.ts перейти на WOFF2 і швидку конвертацію: (а) імпорти шрифтів (рядки 11-12) замінити на .woff2-файли; (б) виклики fetchAsBase64 (рядки 200-203) замінити на fetchAsDataUrl і в шаблоні @font-face (рядки 456-467) писати src: url(${noahRegularDataUrl}) format("woff2"); — FileReader.readAsDataURL повертає готовий data:-URL, btoa і префікс не потрібні; (в) видалити функцію fetchAsBase64 (рядки 153-162) — після заміни в неї не лишиться викликів.
4. Оптимізувати логотип: зменшити frontend/src/assets/logo.png до реального розміру відображення в шапці листа (ціль <30 КБ; через squoosh/ImageOptim/sips) або, якщо візуально прийнятно, перевикористати наявний logo-mark.png (21 КБ). Перевірити вигляд шапки і в застосунку, і в експортованому листі.
5. Прогнати npm run lint і npm run build у frontend/.

## Критерії приймання

- [ ] Експортований HTML-файл типового листа важить приблизно вдвічі-втричі менше, ніж до зміни (орієнтир: службовий вміст шрифти+лого < 250 КБ проти ~560 КБ).
- [ ] Шрифт Noah коректно рендериться в експортованому листі (offline, у браузері без встановленого Noah) і в самому застосунку, включно з українськими літерами і апострофом ʼ.
- [ ] Функції fetchAsBase64 більше немає; вбудовування шрифтів іде через FileReader.readAsDataURL.
- [ ] Логотип у шапці листа і застосунку виглядає без видимої деградації якості (включно з друком).
- [ ] npm run build і npm run lint проходять без помилок.

## Ручна перевірка

> У проєкті немає тест-сьюти — перевірка виконується вручну на локальному дев-середовищі. Жодних дій проти продакшн-БД.

1. Локально: експортувати HTML тестового звіту до і після зміни, порівняти розмір файлів (ls -la).
2. Відкрити новий HTML у браузері з вимкненою мережею (DevTools → Offline) — шрифт Noah застосований (перевірити у DevTools → Rendered Fonts), кирилиця і ʼ рендеряться.
3. Відкрити попередній перегляд друку (Cmd+P) — лого чітке, розкладка не поїхала.
4. У застосунку: жорстке перезавантаження без кешу — у Network вантажаться .woff2 замість .ttf, текст виглядає як раніше.
5. Заміряти час експорту (console.time навколо generateReportHtml або просто субʼєктивно) — затримка помітно менша.
