# B10 · ReferenceItemModal: не скидати введений текст при ре-рендері батька

| Пріоритет | Оцінка | Епік | Залежить від |
|---|---|---|---|
| **P2** | S (до пів дня) | Шлях збереження листа | — |

## Контекст

Модалка ReferenceItemModal (редагування рекомендації до процедури, засобу домашнього догляду, елементів CRUDManager і SearchCategories) ресетить свою форму ефектом `useEffect(() => { setForm(item); }, [item])` (рядки 47–49). Проблема в тому, що всі виклики передають item як новий інлайновий обʼєкт на кожен рендер (напр. CreateReportForm.tsx:857–861, SearchHomeCare.tsx:350–355), тож будь-який ре-рендер батька при відкритій модалці повертає форму до початкових значень. Реальний сценарій: у «Домашньому догляді» триває debounce-пошук засобу (400 мс) — коли запит завершується, setResults/setLoading ре-рендерить компонент, і набраний у модалці текст мовчки зникає. У сусідньому PatientFormModal.tsx:29–36 цю саму ваду вже виправлено (ресет лише по visible) — треба перенести виправлення сюди.

## Кроки реалізації

1. У frontend/src/components/ReferenceItemModal.tsx замінити ефект на рядках 47–49:
```ts
  useEffect(() => {
    setForm(item);
  }, [item]);
```
на ресет лише при відкритті (точно за зразком PatientFormModal.tsx:29–36):
```ts
  // Ресет форми лише при відкритті модалки (false→true) — щоб ре-рендер
  // батька не стирав уже введений текст.
  useEffect(() => {
    if (visible) {
      setForm(item);
    }
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [visible]);
```
2. Виконати `npm run lint` у frontend/.

## Критерії приймання

- [ ] Текст, набраний у відкритій модалці, не зникає при ре-рендерах батьківського компонента (зокрема при завершенні debounce-пошуку в «Домашньому догляді»).
- [ ] При кожному новому відкритті модалка показує актуальні значення переданого item (редагування різних елементів підряд підставляє правильні дані).
- [ ] Усі місця використання модалки (процедури листа, домашній догляд, CRUDManager, SearchCategories) працюють без регресій.

## Ручна перевірка

> У проєкті немає тест-сьюти — перевірка виконується вручну на локальному дев-середовищі. Жодних дій проти продакшн-БД.

1. Локально: у листі тестового пацієнта в «Домашньому догляді» ввести пошуковий запит і, не чекаючи результатів, відкрити редагування вже доданого засобу та почати друкувати; коли пошук завершиться (зникне спінер) — набраний текст має лишитися. До фіксу він скидався.
2. Закрити модалку без збереження, відкрити редагування іншого засобу — поля показують дані саме цього засобу.
3. Швидка регресія: відредагувати рекомендацію процедури у листі та елемент довідника через «Довідники» (CRUDManager) — збереження працює.
