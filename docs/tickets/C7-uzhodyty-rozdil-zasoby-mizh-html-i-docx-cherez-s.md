# C7 · Узгодити розділ «Засоби» між HTML і DOCX через спільний прапорець

| Пріоритет | Оцінка | Епік | Залежить від |
|---|---|---|---|
| **P1** | S (до пів дня) | Експорт: HTML і DOCX | — |

## Контекст

У HTML-експорті розділ «Засоби» вимкнено жорстко: const includeMedicationsSection = false; з коментарем «клієнт попросив тимчасово не включати» (generateReportHtml.ts:288). Але DOCX-гілка (buildDocxFragment.ts:271-277) той самий розділ додає безумовно, щойно у звіті є хоч один засіб. У підсумку лист для пацієнта (HTML) і запис у картці (.docx) розходяться за змістом: пацієнт не бачить «Засобів», а в картці вони є. Це або недогляд при вимкненні розділу, або невідображене бізнес-рішення. Треба зʼясувати у замовника бажану поведінку і технічно звести перемикач в одне місце, щоб наступна зміна діяла на обидва формати одночасно.

## Кроки реалізації

1. Зʼясувати у замовника: чи мають «Засоби» лишатися у картці (.docx), поки вони вимкнені в листі для пацієнта? Зафіксувати відповідь у коментарі в коді.
2. Створити frontend/src/components/ReportForm/reportSectionFlags.ts:
// Клієнт попросив тимчасово прибрати розділ «Засоби» з листа (дата, хто підтвердив).
// Один прапорець керує ОБОМА форматами — HTML і DOCX.
export const INCLUDE_MEDICATIONS_SECTION = false;
Якщо замовник скаже, що в DOCX розділ потрібен — зробити два іменовані прапорці (…_HTML і …_DOCX) у цьому ж модулі, але рішення все одно живе в одному файлі.
3. У frontend/src/components/ReportForm/html/generateReportHtml.ts замінити локальну константу (рядки 287-288) на імпорт INCLUDE_MEDICATIONS_SECTION з нового модуля (умова на рядку 289 стає if (INCLUDE_MEDICATIONS_SECTION && medications.length > 0)).
4. У frontend/src/components/ReportForm/docx/buildDocxFragment.ts обгорнути блок «Засоби» (рядки 271-277) тією самою умовою: if (INCLUDE_MEDICATIONS_SECTION && medications.length > 0) { … } — з імпортом з reportSectionFlags.
5. Прогнати npm run lint і npm run build у frontend/.

## Критерії приймання

- [ ] Розділ «Засоби» або присутній, або відсутній ОДНОЧАСНО в HTML- і DOCX-експорті (відповідно до зафіксованого рішення замовника).
- [ ] Прапорець увімкнення розділу існує рівно в одному модулі, і зміна одного рядка перемикає обидва формати.
- [ ] Нотатка medicationsNote («Важливо») підпорядкована тому самому прапорцю в обох форматах.
- [ ] Рішення замовника зафіксовано коментарем у reportSectionFlags.ts.
- [ ] npm run build і npm run lint проходять без помилок.

## Ручна перевірка

> У проєкті немає тест-сьюти — перевірка виконується вручну на локальному дев-середовищі. Жодних дій проти продакшн-БД.

1. Локально: створити звіт тестового пацієнта з 2 засобами і заповненою нотаткою «Важливо» до засобів.
2. З прапорцем false: експортувати HTML і дописати у тестовий .docx — розділу «Засоби» немає в жодному з файлів.
3. Тимчасово поставити прапорець true, повторити — розділ з обома засобами і нотаткою зʼявився в обох файлах; повернути значення за рішенням замовника.
