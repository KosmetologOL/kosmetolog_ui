# C4 · Експорт «Домашнього догляду»: групувати за вибраними засобами, а не за поточним довідником

| Пріоритет | Оцінка | Епік | Залежить від |
|---|---|---|---|
| **P1** | S (до пів дня) | Експорт: HTML і DOCX | — |

## Контекст

І HTML-, і DOCX-експорт групують вибрані засоби домашнього догляду не за самими вибраними елементами звіту, а за ПОТОЧНИМ станом довідника: обидва генератори викликають getAllHomeCares(), будують список категорій з довідника і фільтрують вибрані засоби по цих назвах. Якщо категорію в довіднику з часу збереження звіту перейменували або видалили — збережені засоби цієї категорії просто не потрапляють у файл, без жодного попередження (додатково порівнюється тримована назва з довідника з нетримованою h.name, тож навіть зайвий пробіл «губить» позиції). Лікар отримує лист без частини призначень і не знає про це. Плюс кожен експорт робить зайвий мережевий запит до довідника. Групувати треба за назвами категорій із самих вибраних елементів — вони самодостатні.

## Кроки реалізації

1. У frontend/src/components/ReportForm/html/generateReportHtml.ts у блоці домашнього догляду (рядки 300-304) замінити:
const allCares = await getAllHomeCares();
const uniqueCategories = Array.from(
  new Set(allCares.map((c) => c.name?.trim()).filter(Boolean)),
);
на:
const uniqueCategories = Array.from(
  new Set(homeCares.map((h) => h.name?.trim()).filter(Boolean)),
);
Порядок категорій при цьому — порядок додавання засобів у звіт (детермінований).
2. Там само у фільтрі (рядок 308) порівнювати тримовані значення: homeCares.filter((h) => h.name?.trim() === category).
3. Прибрати import { getAllHomeCares } from "#api/homeCaresApi"; (рядок 3) — інших використань у файлі немає (type-імпорт IHomeCare на рядку 2 лишити).
4. У frontend/src/components/ReportForm/docx/buildDocxFragment.ts зробити те саме: рядки 282-285 замінити на uniqueCategories з homeCares (як у кроці 1), рядок 288 — фільтр по h.name?.trim() === category, і прибрати import { getAllHomeCares } з рядка 1.
5. Прогнати npm run lint і npm run build у frontend/.

## Критерії приймання

- [x] Засоби категорії, якої більше немає в довіднику (видалена чи перейменована), присутні в HTML- і DOCX-експорті під збереженою у звіті назвою категорії.
- [x] Під час експорту не виконується запит GET до /homecares (довідник більше не потрібен для групування).
- [x] Для звіту з категоріями, що існують у довіднику, вміст розділу «Домашній догляд» не втратив жодної позиції порівняно з поведінкою до зміни.
- [x] npm run build і npm run lint проходять без помилок.

## Ручна перевірка

> У проєкті немає тест-сьюти — перевірка виконується вручну на локальному дев-середовищі. Жодних дій проти продакшн-БД.

1. Локально: в адмін-довіднику створити тестову категорію «Тест-категорія-C4» із засобом, додати її у звіт тестового пацієнта, зберегти.
2. Експортувати HTML і дописати у тестовий .docx — засіб присутній в обох файлах.
3. Видалити «Тест-категорія-C4» з довідника (це власні тестові дані — існуючі записи не чіпати), знову експортувати той самий звіт — засіб все одно присутній в обох файлах.
4. У DevTools → Network переконатися, що під час експорту немає запиту до /homecares.
5. Після перевірки видалити тестового пацієнта/звіт, створені для тесту.
