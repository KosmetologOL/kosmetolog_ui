# C3 · Полагодити невидимі тости експорту HTML і озвучити гілки no-folder/unsupported

| Пріоритет | Оцінка | Епік | Залежить від |
|---|---|---|---|
| **P0** | S (до пів дня) | Експорт: HTML і DOCX | — |

## Контекст

Жодне повідомлення з generateReportHtml.ts користувач не бачить: файл імпортує toast з "react-hot-toast/headless", а <Toaster /> в App.tsx:5 підключено з основного пакета "react-hot-toast". У react-hot-toast@2.6.0 це два незалежні бандли, кожен зі своєю копією стора — диспатчі з headless ніколи не потрапляють у відрендерений Toaster. Наслідок: тост успіху «HTML-файл збережено у обрану папку.», помилки запису/дозволу і «Не вдалося завантажити логотип для звіту.» не показуються взагалі — при помилці запису файл тихо падає у фолбек-завантаження, і лікар не знає, куди подівся лист. Це єдиний файл у проєкті з таким імпортом. Додатково для гілок no-folder/unsupported (коли файл іде звичайним завантаженням) взагалі немає жодного повідомлення — успішний експорт завершується мовчки. Треба виправити імпорт, озвучити всі гілки і поставити ESLint-запобіжник, щоб автокомпліт IDE не повернув проблему.

## Кроки реалізації

1. У frontend/src/components/ReportForm/html/generateReportHtml.ts рядок 13 замінити на: import toast from "react-hot-toast"; (default-імпорт, як у решті 18 файлів проєкту).
2. Там само в обробці результату saveHtmlBlob (рядки 925-935) додати гілку для reason "no-folder" і "unsupported": після блоку permission-denied дописати } else { toast.success("HTML-файл завантажено у папку «Завантаження»."); } — saveHtmlBlob (frontend/src/lib/htmlSaveLocation.ts:41-54) повертає ці reason саме тоді, коли файл пішов звичайним завантаженням.
3. У frontend/eslint.config.js у конфіг-обʼєкт (після languageOptions, рядок 21) додати: rules: { "no-restricted-imports": ["error", { paths: [{ name: "react-hot-toast/headless", message: "Імпортуйте toast з \"react-hot-toast\" — headless-стор не рендериться нашим <Toaster />." }] }] },
4. Прогнати npm run lint і npm run build у frontend/.

## Критерії приймання

- [ ] Після успішного збереження у вибрану папку зʼявляється видимий тост «HTML-файл збережено у обрану папку.».
- [ ] Коли файл іде звичайним завантаженням (папку не вибрано або браузер без File System Access) — зʼявляється тост «HTML-файл завантажено у папку «Завантаження».»; жодна гілка експорту не завершується мовчки.
- [ ] Тости помилок write-failed / permission-denied видимі.
- [ ] npm run lint падає з помилкою, якщо будь-де зʼявляється import з "react-hot-toast/headless" (перевірено тимчасовим поверненням старого імпорту).
- [ ] grep -rn "react-hot-toast/headless" frontend/src не знаходить жодного входження.

## Ручна перевірка

> У проєкті немає тест-сьюти — перевірка виконується вручну на локальному дев-середовищі. Жодних дій проти продакшн-БД.

1. Локально в Chrome: у формі листа тестового пацієнта натиснути «Створити HTML», вибрати тестову папку — тост успіху зʼявився у правому верхньому куті, файл у папці.
2. Повторити і скасувати вибір папки (Escape) — файл падає у «Завантаження», зʼявляється тост «HTML-файл завантажено у папку «Завантаження».».
3. У Firefox (без File System Access) експортувати — файл завантажується, тост про «Завантаження» видно.
4. Тимчасово повернути import з headless → npm run lint показує помилку no-restricted-imports; повернути правильний імпорт → lint чистий.
