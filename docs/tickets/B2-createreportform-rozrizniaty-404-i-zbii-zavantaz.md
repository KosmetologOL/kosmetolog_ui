# B2 · CreateReportForm: розрізняти 404 і збій завантаження листа, екран помилки з повтором

| Пріоритет | Оцінка | Епік | Залежить від |
|---|---|---|---|
| **P0** | S (до пів дня) | Шлях збереження листа | — |

## Контекст

При відкритті листа форма робить getReportByPatientId(patientId).catch(() => null) (CreateReportForm.tsx:175) — БУДЬ-ЯКА помилка (500, таймаут, обрив мережі) трактується як «листа ще немає», хоча бекенд повертає 404 лише коли звіту справді не існує (reports.controller.ts:61–63). При збої форма відкривається порожньою з reportId=null, і «Зберегти лист» викликає createReport — на бекенді створюється ДРУГИЙ звіт для того ж пацієнта, після чого findOne повертає один із двох і робота лікаря «роздвоюється». Збій повністю тихий: помилка вже поглинута, тому ні тост у catch (рядки 276–278), ні глобальний обробник її не бачать. Аналогічно getSettings().catch(() => ({})) (рядок 176) мовчки губить типові тексти «Важливо». З огляду на відсутність бекапів БД це прямий ризик втрати клінічних даних. Бекендова частина захисту (unique-індекс + 409) — окремий тікет B3.

## Кроки реалізації

1. У frontend/src/components/ReportForm/CreateReportForm.tsx додати `import axios from "axios";` до блоку імпортів.
2. Додати стани поряд з loading (рядок 116): `const [loadError, setLoadError] = useState(false);` та `const [reloadKey, setReloadKey] = useState(0);`.
3. Рядок 175: замінити `getReportByPatientId(patientId).catch(() => null),` на:
```ts
          getReportByPatientId(patientId).catch((error: unknown) => {
            if (axios.isAxiosError(error) && error.response?.status === 404) {
              return null;
            }
            throw error;
          }),
```
4. Рядок 176: замінити `getSettings().catch((): ISettings => ({})),` на `getSettings(),` — збій налаштувань має падати в той самий catch, а не мовчки обнуляти типові тексти. З імпорту на рядку 9 прибрати невикористаний `type ISettings`.
5. На початку fetchData (після `if (!patientId) return;`, рядок 171) додати `setLoadError(false);`. У catch (рядки 276–278) замінити тост на `setLoadError(true);` (екран помилки пояснить ситуацію, тост дублюватиме).
6. У деписи ефекту (рядок 283) додати reloadKey: `}, [patientId, reloadKey]);`.
7. У ефекті знімка чистого стану (рядки 286–290) додати захист від помилки: `if (!loading && !loadError && savedSnapshot === null)`.
8. Після блоку `if (loading) return (…)` (рядки 590–607) додати екран помилки — форма при цьому не рендериться, тож зберегти (і створити дубль) неможливо:
```tsx
  if (loadError)
    return (
      <div className="py-12 text-center">
        <p className="text-ink-soft">
          Не вдалося завантажити лист. Перевірте зʼєднання і спробуйте ще раз.
        </p>
        <button
          type="button"
          onClick={() => {
            setLoading(true);
            setReloadKey((k) => k + 1);
          }}
          className="btn btn-primary mt-4"
        >
          Спробувати ще раз
        </button>
      </div>
    );
```
9. Виконати `npm run lint` у frontend/.

## Критерії приймання

- [ ] Якщо бекенд відповів 404 на GET /reports/patient/:patientId — форма відкривається порожньою (новий лист), як і раніше.
- [ ] Якщо запит листа або налаштувань упав з будь-якою іншою помилкою — замість порожньої форми показується екран «Не вдалося завантажити лист…» із кнопкою «Спробувати ще раз»; кнопки збереження недоступні (форма не відрендерена).
- [ ] Кнопка «Спробувати ще раз» повторює завантаження і при успіху показує заповнену форму з reportId наявного листа.
- [ ] Після збою завантаження неможливо створити другий звіт для пацієнта, у якого лист уже існує.

## Ручна перевірка

> У проєкті немає тест-сьюти — перевірка виконується вручну на локальному дев-середовищі. Жодних дій проти продакшн-БД.

1. Локально: запустити обидва dev-сервери, відкрити лист тестового пацієнта, в якого лист уже існує, — форма заповнена (регресії немає).
2. Зупинити бекенд (Ctrl+C у backend/), перезавантажити сторінку листа: має зʼявитися екран помилки з кнопкою «Спробувати ще раз», а не порожня форма.
3. Запустити бекенд знову, натиснути «Спробувати ще раз»: форма завантажується з даними наявного листа; «Зберегти лист» виконує оновлення (у mongosh read-only перевірити: db.reports.countDocuments({ patient: ObjectId("<id>") }) === 1).
4. Відкрити лист пацієнта без звіту (бекенд працює): форма порожня, збереження створює перший звіт — 404-гілка працює.
