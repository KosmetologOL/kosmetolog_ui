# F6 · Узгодити підтвердження: видалення процедури з листа та деактивація лікаря

| Пріоритет | Оцінка | Епік | Залежить від |

| **P2** | S (до пів дня) | Фронтенд і UX | — |

## Контекст

Два місця порушують власні конвенції підтверджень проєкту. (1) Хрестик біля процедури в етапі листа видаляє її миттєво — разом із вручну відредагованою рекомендацією і памʼяткою (NoteField), які не відновити; при цьому видалення цілого етапу підтвердження має. (2) Деактивація лікаря — асинхронна дія зі спінером «Зберігаємо…», але підтверджується через window.confirm, тоді як конвенція проєкту (CLAUDE.md) для асинхронних дій з in-progress станом вимагає ConfirmModal — і в цьому ж файлі видалення лікаря вже зроблено через ConfirmModal, тобто компонент неконсистентний сам із собою.

## Кроки реалізації

1. frontend/src/components/ReportForm/ProcedureStageCard.tsx:152–165 — у onClick кнопки × додати синхронне підтвердження (window.confirm тут дозволений конвенцією), якщо є що втрачати:
```tsx
onClick={() => {
  const hasContent = proc.comment?.trim() || proc.recommendation?.trim();
  if (
    hasContent &&
    !window.confirm(
      `Видалити процедуру «${proc.name}»? Разом з нею буде втрачено памʼятку та відредаговану рекомендацію.`,
    )
  ) {
    return;
  }
  patchStage({
    procedures: stage.procedures.filter((p) => p._id !== proc._id),
  });
}}
```
2. frontend/src/components/Admin/DoctorsManager.tsx: додати стан `const [deactivatingDoctor, setDeactivatingDoctor] = useState<IDoctor | null>(null);`.
3. Розділити toggle (рядки 32–56): винести тіло запиту в `const performToggle = async (doctor: IDoctor) => { … }` (поточні рядки 42–55 без window.confirm); сам toggle: якщо doctor.active → setDeactivatingDoctor(doctor), інакше → void performToggle(doctor).
4. Поруч із наявним ConfirmModal видалення (158–166) додати другий ConfirmModal: visible={Boolean(deactivatingDoctor)}, title="Деактивувати лікаря", message=`Деактивувати акаунт лікаря ${deactivatingDoctor?.name?.trim() || deactivatingDoctor?.email}? Він втратить доступ до системи.`, isLoading={togglingId !== null}, loadingLabel="Деактивуємо…", onConfirm={async () => { if (deactivatingDoctor) { await performToggle(deactivatingDoctor); setDeactivatingDoctor(null); } }}, onCancel={() => setDeactivatingDoctor(null)}.
5. Переконатися, що window.confirm у DoctorsManager (рядки 36–39) видалено; активація (неактивний → активний) лишається без підтвердження.

## Критерії приймання

- [x] Хрестик процедури з непорожньою памʼяткою або рекомендацією питає підтвердження з назвою процедури; процедура без памʼятки і рекомендації видаляється одразу, як раніше.
- [x] Скасування у confirm лишає процедуру та її памʼятку недоторканими.
- [x] Деактивація лікаря відбувається через ConfirmModal зі станом «Деактивуємо…»; window.confirm для цієї дії більше не викликається.
- [x] Активація лікаря працює одразу, без модалки.
- [x] `npm run lint` у frontend/ чистий.

## Ручна перевірка

> У проєкті немає тест-сьюти — перевірка виконується вручну на локальному дев-середовищі. Жодних дій проти продакшн-БД.

1. У формі листа: додати процедуру в етап, вписати памʼятку, натиснути × — зʼявляється confirm з назвою; «Скасувати» — нічого не зникло; «OK» — процедура і памʼятка видалені.
2. Додати процедуру без памʼятки і з порожньою рекомендацією — × видаляє без питань.
3. Довідники → Лікарі: на ТЕСТОВОМУ лікарі натиснути «Деактивувати» — відкривається модалка з імʼям; підтвердити — кнопка показує «Деактивуємо…», статус змінюється, тост зʼявляється; «Активувати» — без модалки.
